# Campaign: Make the System Remember

## Objective

Move cognitive accessibility from display accommodations into operating-system behavior. The campaign asks Apple and other platform providers to reduce avoidable recall, naming, filing, and recovery burdens.

## Initial audience

Start with the technology and creative industries:

- independent musicians and producers;
- video editors and filmmakers;
- game developers;
- designers and photographers;
- creative-tool developers;
- accessibility researchers;
- operating-system file, search, automation, and accessibility teams.

## The change request

Ask operating-system providers to support a system-level Device Steward interface that can:

1. accept natural-language intent from any creative application;
2. generate accessible filenames, versions, tags, and destinations;
3. maintain a user-owned provenance manifest;
4. retrieve files through human descriptions and project relationships;
5. show a reversible preview before organizational actions;
6. preserve task state so people can resume after interruption;
7. expose learned rules for inspection, correction, export, and deletion; and
8. provide an open API so assistive tools can participate without screen scraping.

## Campaign sequence

### Phase 1 — Document

- Publish the launch post and repository.
- Collect consented, de-identified creative workflow cases.
- Map each case to a reproducible interface failure and a proposed design pattern.

### Phase 2 — Demonstrate

- Build an iPad-first, read-only prototype that generates names and destinations without moving files.
- Test the Artist File Protocol with independent creators.
- Publish results, failures, and revisions—not testimonials alone.

### Phase 3 — Submit

- Submit a concise, reproducible request through Apple Product Feedback for iPad and iCloud.
- Send accessibility-specific questions through Apple Accessibility Support.
- Submit equivalent findings through Android accessibility feedback and relevant Microsoft accessibility channels.
- Send design-pattern findings to the W3C Cognitive and Learning Disabilities Accessibility Task Force.

### Phase 4 — Convene

- Invite DAW, NLE, game-engine, cloud-storage, and operating-system teams to a public design review.
- Publish a platform-neutral reference implementation and interoperability proposal.
- Track provider responses and product changes in a public campaign ledger.

## Evidence standard

Each campaign claim must link to:

- a consent-cleared case record;
- steps to reproduce;
- the current platform behavior;
- the access need affected;
- the proposed change;
- known risks and limitations; and
- the provider submission date and response status.

Do not make a person identifiable merely to make the campaign emotionally stronger.

## Measures of campaign progress

- consented case studies collected;
- creative applications represented;
- prototype tasks completed with fewer prompts;
- provider submissions acknowledged;
- public issues or standards discussions opened;
- OS or application behavior changed;
- adopted open interfaces or design patterns.
